Installation

Install Guardian on a target machine using the Debian package.

1. Download & Install

Download the .deb package from the Repository page and transfer it to the target machine. 

# Install the package (or upgrade an existing installation)
sudo dpkg -i guardian_*.deb

# If there are missing dependencies, fix them
sudo apt-get install -f

This installs guardiand, guardian-cli, and license-gen into /usr/local/bin/, along with the default config and systemd unit file. The service is automatically enabled on boot via systemctl enable guardian.

Upgrading or reinstalling?

The package handles previous installations automatically. On upgrade it stops the running daemon, cleans up stale socket and PID files, installs the new binaries, and restarts the daemon. Your /etc/guardian/guardian.conf is preserved across upgrades.

2. Export Hardware Info

Generate a hardware fingerprint file from the target machine. This captures the machine ID, CPU, motherboard, disk serial, and NIC MAC address. 

sudo guardian-cli export-hardware > hardware-info.json

Next: Upload this to Guardian Manager

Transfer hardware-info.json to your admin machine and upload it via Projects → Add Hardware Config in the Guardian Manager web panel. Then create a license for this hardware — the signed .license file and master.pub key will be available for download from the Repository.

3. Deploy License & Keys

Copy the public key and signed license file to the target machine. Both are available for download from the Repository. 

sudo cp master.pub /etc/guardian/master.pub
sudo cp customer.license /etc/guardian/guardian.license

Expected file layout after setup:

/etc/guardian/
  guardian.conf          # Configuration (installed by .deb)
  master.pub             # Signing public key
  guardian.license        # Signed license file

4. Start the Daemon

The service is already enabled on boot by the installer. Start it for the first time: 

sudo systemctl start guardian

The daemon will start automatically on subsequent reboots. To check auto-start status: 

# Confirm the service is enabled for auto-start on boot
sudo systemctl is-enabled guardian

# If not enabled (e.g. manually disabled), re-enable it
sudo systemctl enable guardian

5. Verify Installation

Confirm that the daemon is running and the license is valid:

# Check service status
sudo systemctl status guardian

# Check daemon health and license validity
guardian-cli --config /etc/guardian/guardian.conf status

# View decoded license details
guardian-cli license-info

# Compare hardware fingerprints (expected vs actual)
guardian-cli hardware-info

A healthy installation will show active (running) for the service, a valid license status, and matching hardware fingerprints above the configured threshold.

6. Troubleshooting

If the daemon fails to start or the license is rejected, use these commands to diagnose the issue:

# Check daemon logs for errors
sudo journalctl -u guardian -n 50 --no-pager

# Verify the license signature independently
license-gen verify --license=/etc/guardian/guardian.license \
  --pub=/etc/guardian/master.pub

# Check that the socket file exists
ls -la /var/run/guardian/guardian.sock

# Check file permissions
ls -la /etc/guardian/

License invalid

The hardware fingerprint may not match. Run guardian-cli hardware-info to see which components differ. If fewer components match than the configured threshold (default 3 of 5), the license is rejected.

Socket not found

The daemon did not start. Check logs with journalctl -u guardian and verify that the license and public key files exist at the paths specified in /etc/guardian/guardian.conf.

Permission denied

Ensure config, license, and key files are readable by the guardian service user. The socket at /var/run/guardian/guardian.sock should have mode 0666 so client processes can connect.

Signature verification failed

The public key on the target machine does not match the private key that signed the license. Re-download the correct master.pub from the Repository.

7. Uninstall

The package automatically stops and disables the daemon on removal. 

# Remove Guardian (keeps config files in /etc/guardian/)
sudo dpkg -r guardian

# Or purge completely (removes package + cleans runtime state)
sudo dpkg -P guardian

# After purge, manually remove config/license if no longer needed
sudo rm -rf /etc/guardian/
